# Исходные скрипты (архив)

Это первая версия обхода — набор `.cmd` + `.ps1`, из которого выросла утилита
`OpencodeDpiFix.exe`. Скрипты рабочие, но требуют запуска «от имени администратора»
правым кликом и пугают PowerShell'ом; exe делает то же самое одним окном.

Оставлено для прозрачности: видно, что именно происходит с файлом `hosts`.

Использование прежнее:

1. `1-установить.cmd` — правый клик → «Запуск от имени администратора».
2. `2-проверить.cmd` — проверить доступность доменов.
3. `3-удалить.cmd` — убрать записи.

---

# Обход блокировки opencode.ai — комплект для домашнего ПК

Положите эту папку куда угодно (например, `F:\dima\obhod`) и выполните на домашнем
компьютере три шага. Права администратора нужны только для первого.

---

## Быстрый старт

1. **`1-установить.cmd`** — правый клик → «Запуск от имени администратора».
   UAC спросит подтверждение, это нормально.
2. **`2-проверить.cmd`** — должен показать `OK` по всем трём доменам.
3. Закройте и заново откройте браузер и приложение opencode.

Всё. Больше ничего запускать не нужно, фоновых процессов и служб не появляется.

---

## Что именно делает установка

Дописывает в `C:\Windows\System32\drivers\etc\hosts` три строки:

```
8.47.69.5	opencode.ai
8.47.69.5	models.dev
8.47.69.5	registry.npmjs.org
```

Они заключены в блок с маркерами, поэтому повторный запуск не создаёт дубликатов,
а `3-удалить.cmd` убирает ровно этот блок.

**Почему это работает.** Провайдерский DPI режет не по имени сайта и не по IP,
а по содержимому TLS-рукопожатия: если клиент предлагает post-quantum ключ
(`X25519MLKEM768`, ~1.5 КБ), соединение молча сбрасывается. Классический `X25519`
на том же самом IP проходит. Адрес `8.47.69.5` — тот же Cloudflare, но правило
на нём не применено: проверено, что он отдаёт эти хосты даже с PQ-рукопожатием.
Поэтому достаточно направить домены туда — браузер, приложение, CLI и npm
начинают работать без прокси и без VPN.

## Если что-то не так

**`2-проверить.cmd` показывает ОШИБКА / висит HTTPS.**
Значит записи не применились. Проверьте, что `1-установить.cmd` запускался от
администратора, и что в выводе было `OK`.

**Сайт открывается, но медленно, или не открывается при рабочем IPv4.**
Скорее всего, у провайдера есть IPv6, и браузер пробует идти по нему. Тогда в
командной строке от администратора (или прямо в этом окне после шага 1):

```
1-установить.cmd -BlockIPv6
```

Это дополнительно прописывает `::1` для трёх доменов — IPv6-попытка отклоняется
мгновенно, браузер сразу берёт IPv4.

**`8.47.69.5` перестал отвечать** (провайдер расширил правило). Возьмите резервный
адрес:

```
1-установить.cmd -EdgeIPv4 8.6.112.5
```

Команду нужно выполнять от администратора. Проверить после — снова `2-проверить.cmd`.

**Не помогают оба адреса.** Тогда правило накрыло все диапазоны Cloudflare,
и остаётся только VPN.

---

## Как удалить

`3-удалить.cmd` — правый клик → «Запуск от имени администратора».
Файл `hosts` вернётся к состоянию до установки.

**Где остаются следы:** только резервные копии `hosts.bak-*` в
`C:\Windows\System32\drivers\etc\`. Их можно удалить вручную.

## Файлы в папке

| Файл | Назначение |
|---|---|
| `1-установить.cmd` | Включить обход (поднимает UAC) |
| `2-проверить.cmd` | Проверить доступность трёх доменов |
| `3-удалить.cmd` | Убрать записи (поднимает UAC) |
| `apply-hosts.ps1` | Логика установки/удаления. Можно запускать вручную с параметрами `-DryRun`, `-EdgeIPv4`, `-BlockIPv6`, `-Revert` |
| `check.ps1` | Логика проверки. Ничего не меняет |

---

## Отличия от того, что сделано на рабочем ПК

На работе прав администратора нет, поэтому там используется фоновый прокси-процесс,
переменные окружения и системный прокси. Дома с правами администратора это не нужно:
`hosts` действует на **все** программы сразу (браузер, Electron-приложение, CLI, npm)
и не требует ни запущенного процесса, ни настроек прокси.

## Проверка вручную, без скриптов

```
powershell -NoProfile -c "Resolve-DnsName opencode.ai -Type A | Where-Object IPAddress | Select-Object -ExpandProperty IPAddress"
```

Ожидается `8.47.69.5`. Если видите `172.65.90.x` — записи нет.
